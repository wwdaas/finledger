# Redis 使用边界

FinLedger 的账户余额、转账订单、交易流水和幂等结果都以 MySQL 为最终事实来源。
Redis 当前只用于转账接口的固定窗口限流。

限流脚本使用 Lua 将 `INCR` 和首次设置过期时间组合为一次原子操作，key 按用户隔离。
默认每位用户每 60 秒最多请求 20 次，超过限制返回 HTTP 429。

当前采用 fail-open 策略：Redis 暂时不可用时记录告警，但不影响 MySQL 中的核心转账事务。
这是可用性优先的明确取舍；如果部署环境更强调防滥用，可以改为 fail-closed。

Redis 不承担以下职责：

- 不保存权威余额；
- 不代替 MySQL 事务或行锁；
- 不作为转账幂等的唯一保证；
- 不决定一笔转账是否成功。
